# CTRS 평가 모델 (Synap 상담 챗봇)

## 프로젝트 배경
- 인공지능 캡스톤디자인 프로젝트 "Synap: CBT 기반 상담 챗봇 서비스" (팀 시냅스, 개발 지예, 현수)
- 소프트웨어학과 교수님 면담에서 정량지표 부재를 지적받음 (챗봇 목표, 파인튜닝이 별로라고 판단한 기준이 없음)
- 평가 목표를 CACTUS 논문과 동일하게 CTRS(Cognitive Therapy Rating Scale) 6개 항목으로 정함
- 이 레포는 상담 대화를 입력받아 CTRS 6개 항목 점수를 매기는 LLM 평가자(LLM-as-a-judge)를 만드는 곳임
- 담당: 지예 (평가 모델 제작, 보고서, 김은하 교수님 검증). 파인튜닝 재진행과 프롬프팅은 현수 담당

## 평가 항목 (prompts/ 폴더, 파일 1개 = 항목 1개)
일반 상담기술
- general_1_understanding: 이해 (반영, 재진술, 감정과 의미 파악)
- general_2_interpersonal_effectiveness: 대인관계 효과성 (따뜻함, 전문성, 비판 여부)
- general_3_collaboration: 협력 (선택권 제공, 목표 공동 결정)

CBT 기술
- CBT_1_guided_discovery: 유도된 발견 (질문, 증거 검토, 대안 탐색)
- CBT_2_focus: 핵심 인지, 행동 초점 (자동사고, 신념, 회피행동 탐색)
- CBT_3_strategy: 변화전략 (문제에 적절한 CBT 전략의 선택과 일관성)

프롬프트 규칙
- 각 프롬프트의 `{conversation}` 자리에 대화 전문을 넣어 호출함
- 점수 범위 0~6 정수 (사이일 경우 홀수 1, 3, 5)
- 출력 형식은 "점수, 설명" (쉼표 구분). 설명 안에도 쉼표가 있으므로 반드시 첫 번째 쉼표 기준으로 분리할 것
- 프롬프트 원문은 CACTUS 기준이므로 임의로 수정하지 않음. 형식 변경(JSON 출력 등)이 필요하면 별도 파일로 만들고 원본은 보존

## 현재 단계
- 베이스 모델, 파인튜닝 모델이 아직 없음. 평가 모델을 먼저 만들어두는 단계
- 평가 모델 검증용 데이터는 CACTUS 데이터셋 사용
- 나중에 챗봇이 나오면 GPT 내담자 시뮬레이션으로 대화를 생성해 같은 파이프라인에 넣을 예정
- 따라서 파이프라인은 "대화 텍스트만 바꿔 끼우면 되는" 구조여야 함

## 해야 할 일
1. 평가 파이프라인 코드 (Python)
   - prompts/ 폴더의 파일을 자동으로 읽어 항목 목록 구성 (항목 추가 시 파일만 넣으면 되게)
   - 대화 1개당 항목 수만큼 API 호출, 실패 시 재시도
   - 파싱: 첫 번째 쉼표 기준 분리, 점수가 0~6 정수인지 검증, 실패 시 원문 응답 보존
   - 결과 저장: 대화 ID, 대화 원문, 항목, 점수, 설명, 평가 모델명, 설정값, 실행 회차
   - 대화 원문과 설명까지 전부 저장할 것 (나중에 "CTRS 점수는 높은데 실제로는 반복이 심한" 사례를 찾아 지표 추가 근거로 쓰기 위함)
   - 계산형 보조 지표(예: 반복률)를 나중에 열 하나로 붙일 수 있는 구조
2. 평가 모델(judge) 후보 비교 실험
   - 후보: GPT 계열 1~2개 + 오픈 모델 1~2개, 프롬프트는 동일
   - 모델 버전(스냅샷) 고정, temperature 0
3. 망가뜨린 대화(perturbation) 생성
   - CACTUS 원본은 점수가 다 높게 나와 변별이 안 될 수 있으므로 일부러 품질을 떨어뜨린 버전을 함께 사용
   - 반복 → 이해 하락 기대 / 설교, 설득 → 유도된 발견 하락 / 공감 제거 → 대인관계 효과성 하락 / 일방적 지시 → 협력 하락 / 자동사고와 무관한 잡담 → 핵심 인지 초점 하락
4. 비교 기준
   - 변별력: 원본 대비 망가진 버전에서 해당 항목 점수가 떨어지는가
   - 일관성: 같은 대화 3~5회 반복 채점 시 점수 분산
   - 전문가 일치도: 김은하 교수님이 일부 샘플(10개 내외)을 채점하면 모델 점수와 상관 계산
   - 비용과 속도
5. 보고서: CTRS 선정 이유, 6개 항목 선정 이유(CACTUS 선행 근거), 평가 모델 선정 근거(위 비교 표)

## 비용 관련
- OpenAI API는 ChatGPT 구독과 별개인 종량제
- 먼저 대화 5개 정도로 파이프라인, 파싱 확인 후 전체 실행
- 결과를 즉시 받을 필요 없는 실험은 Batch API 사용 (50% 할인)
- 일관성 반복 채점은 일부 샘플에만 적용
- API 키는 .env로 관리하고 절대 커밋하지 않음

## 지표 추가 방침
- 우선 CTRS 6개 항목만으로 진행
- 베이스, 파인튜닝 모델 재학습 후에도 문제(반복 등)가 CTRS 점수로 잡히지 않으면, 그 사례를 근거로 지표 추가 검토

## 폴더 구조
- prompts/: CTRS 항목별 평가 프롬프트 (원본)
- data/: CACTUS 샘플, 망가뜨린 버전
- 결과물은 results/ 등에 저장

## 작성 규칙
- 문서 작성 시 중간점과 em-dash 사용하지 않음 (쉼표, 마침표, 괄호로 대체)
- 문서 종결어미는 개조식(임, 음, 함)
